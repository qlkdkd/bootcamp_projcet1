# AI 사용 기록

비전검사 로그 통합 처리 프로그램을 만들면서 AI 코딩 도구를 어떻게 썼는지 기능별로 정리한 문서입니다.
기능마다 **요청한 내용 → AI가 만든 결과 → 확인한 방법 → 고친 부분** 순서로 적었습니다.
대화 원문은 [AI_Log.md](../AI_Log.md)에 있습니다.

## 1. 사용 환경

| 항목 | 내용 |
|---|---|
| 도구 | Claude Code (Claude 데스크톱 앱의 Code 탭) |
| 모델 | Claude Opus 5.5 |
| 사용 날짜 | 2026-11-23 |
| AI가 한 일 | PDF와 데이터 읽기, 코드 작성, 실행·테스트, 브라우저로 Dash 화면 확인, 문서 초안 작성 |
| 내가 한 일 | 요청, 결과 검토, 코드 주석 보강, README 화면 캡처 추가, 발표 준비 |

## 2. 전체 진행 흐름

| 순서 | 요청 내용 | AI가 만든 결과 |
|---|---|---|
| 1 | "pdf에 쓰여있는 내용을 기반으로 파이썬 코드를 써줘" | 프로그램 전체 (`main.py`, `app.py`, `vision_log/` 모듈 5개, `config.json`, `requirements.txt`, `README.md`) |
| 2 | "각각의 요구사항(F1~F11, D1~D7, S1~S6)을 어떻게 구현했는지 설명해줄 수 있어?" | 요구사항 번호별 구현 위치·방법 표, 발표 때 질문이 나올 만한 부분 정리 |
| 3 | "코드 파일마다 정해진 역할을 써놓은 UML을 작성해줄 수 있어?" | [docs/uml.md](uml.md) (클래스 다이어그램, 실행 순서 시퀀스 다이어그램) |
| 4 | "모든 파일의 함수에 대한 설명을 하나하나씩 해줄 수 있어?" | 함수별 입력·출력·동작 설명 → [function_explain.md](../function_explain.md)로 저장 |
| 5 | "AI 활용과 코드 설명 자료를 만들어줘" | 이 문서와 [docs/code_explanation.md](code_explanation.md) |

처음 요청 한 번으로 프로그램 전체를 만들고, 그 뒤의 요청은 **코드를 이해하고 설명하기 위한 것**이었습니다.
기능별 요청을 따로 하지 않았으므로, 아래 기능별 기록의 "요청 내용"은 첫 요청에 함께 들어간 PDF 요구사항 문장입니다.

## 3. 코드 작성 전에 AI가 확인한 것

AI는 코드를 쓰기 전에 PDF 6쪽 전체와 CSV 4개를 읽고, 데이터에 문제가 있는지 먼저 검사했습니다.

| 검사 항목 | 결과 |
|---|---|
| 파일별 줄 수 | A 1,966 / B 1,352 / C 1,880줄. PDF에 적힌 숫자와 같음 |
| 시각 형식 오류 | 없음 |
| 중복 행, 중복 일련번호 | 없음 |
| NG인데 불량 코드가 없는 행, OK인데 코드가 있는 행 | 없음 |
| 시설별 NG 수 | A 101 / B 56 / C 81건 (합계 238건) |
| 처리 시간 최댓값 | A시설만 5,000ms (나머지는 120ms 정도) |
| 한글 글꼴 | 맑은 고딕 설치 확인 |
| 패키지 | pandas, numpy, matplotlib는 있었고 dash는 없어서 설치함 |

이 결과에 따라 데이터 정리 코드는 최소한으로 두되, 다른 데이터가 들어와도 안전하도록 공백 제거·대문자 변환·형식 오류 행 제외는 넣었습니다.

## 4. 기능별 기록

### F1~F3. 로그 읽기, 합치기, 불량코드 결합

- **요청 내용**: "입력 폴더 안의 facility_로 시작하는 파일을 모두 읽는다. 파일 이름이나 개수를 코드에 적지 않는다." / "합치고 검사 시각 순서로 정렬해 저장한다." / "불량코드표를 결합해 불량 이름, 분류, 심각도 열을 추가한다."
- **받은 결과**: `vision_log/loader.py`의 `find_log_files`, `read_log_file`, `read_all_logs`, `merge_logs`, `read_defect_codes`, `attach_defect_info`, `load_dataset`
  - 파일은 `glob("facility_*.csv")`로 찾고, 앞부분 `facility_`도 설정 파일에서 받음
  - 시각을 datetime으로 바꾼 뒤 정렬
  - 불량코드표는 `merge(how="left")`로 붙여 OK 기록이 빠지지 않게 함
- **확인한 방법**: 합친 행 수가 5,198줄(1,966+1,352+1,880)인지 확인. `all_facility_log.csv`를 열어 시각 순서와 불량 이름 열 확인.
- **직접 고친 부분**: `loader.py`에 주석을 덧붙임
  - `setup_logger` 설명에 로그 형식(`시각[수준] 메시지`) 추가
  - `read_log_file`의 단계마다 무슨 일을 하는지 주석 추가 (읽기 실패 처리, 공백 제거, 대문자 변환 이유, datetime 변환, 숫자 변환)
  - `find_log_files`의 반환값이 무엇인지 주석 추가

### F4~F7. 시설별·종류별·날짜별·카메라별 집계

- **요청 내용**: "시설별 검사 수, 불량 수, 불량률(%, 소수 둘째 자리)" / "시설별·불량 종류별 표와 불량 분류별 표" / "날짜별·시설별 검사 수와 불량률" / "카메라별 검사 수와 불량률"
- **받은 결과**: `vision_log/analysis.py`의 `facility_summary`, `facility_defect_table`, `category_table`, `daily_facility_summary`, `camera_summary`
  - 불량률 계산을 `_rate_table` 함수 하나에 모으고, 묶는 기준(시설 / 날짜+시설 / 카메라)만 바꿔 쓰는 구조
  - 합계 행의 불량률은 시설별 불량률의 평균이 아니라 합계 숫자로 다시 계산
- **확인한 방법**: 시설별 불량 수가 처음 데이터 검사에서 센 숫자(101 / 56 / 81)와 같은지 비교. 시설 x 불량 종류 표의 합계가 238인지 확인.
- **직접 고친 부분**: `main.py`의 각 집계 호출 위에 어떤 표를 만드는지 주석을 추가함. 코드 로직은 바꾸지 않음.

### F8. 이상 기록 목록

- **요청 내용**: "판정 불가(D99)이거나 처리 시간이 기준값(기본 1000ms)을 넘는 기록을 모아 CSV로 저장한다."
- **받은 결과**: `find_anomalies` 함수. 왜 이상 기록인지 알 수 있게 `이상 사유` 열을 맨 앞에 붙임.
- **확인한 방법**: 결과 11건이 모두 2026-11-20 A-CAM1의 D99 기록이고, 처리 시간이 모두 5,000ms인지 확인. 기준값을 500ms로 바꿔도 11건이라, 처리 시간이 긴 기록은 모두 D99 기록이라는 것도 확인.
- **AI가 테스트 중 고친 부분**: 처음에는 `apply`로 `이상 사유`를 만들었는데, Dash에서 이상 기록이 0건인 조건(예: B시설만 선택)을 테스트하자 `ValueError`가 났습니다. 결과가 비어 있으면 `apply`가 Series가 아니라 DataFrame을 돌려주기 때문입니다. numpy 배열로 문자열을 만드는 방식으로 바꿔 해결했습니다.
- **직접 고친 부분**: `main.py`에 주석 추가.

### F9. 조건으로 기록 골라내기

- **요청 내용**: "시설, 날짜 범위, 불량 종류를 조건으로 기록을 골라 CSV로 저장한다. 조건은 일부만 주어도 동작해야 한다."
- **받은 결과**: `filter_records` 함수와 명령 인자 `--facility`, `--start`, `--end`, `--defect`
  - 처음에는 모든 행이 True인 마스크로 시작하고, 주어진 조건만 하나씩 더하는 방식
  - 끝 날짜는 그날 하루 전체가 들어가도록 `< 끝날짜 + 1일`로 비교
  - 불량 종류는 코드(D01)와 이름(찍힘) 둘 다 받음
- **확인한 방법**: `--facility A시설 --start 2026-11-17 --end 2026-11-18 --defect D01 찍힘`으로 실행해 25건이 나오는 것을 확인.
- **직접 고친 부분**: 없음.

- **요청 내용**: "시설별 불량 종류 건수 그래프와 날짜별 시설 불량률 추이 그래프를 PNG로 저장한다. 제목, 축 이름, 범례에 한글이 깨지지 않아야 한다."

### D1~D7. Dash 화면

- **요청 내용**: PDF 4쪽 D1~D7 (실행 방법, 선택 요소, 요약 숫자, 그래프 2개, 표 2개, 선택에 따른 재계산, 집계 함수 재사용과 1회 읽기)
- **받은 결과**: `app.py`
  - 로그는 파일을 실행할 때 한 번만 읽어 `DF`에 둠
  - 콜백 함수 `update` 하나가 선택 4개를 받아 카드·그래프·표 전부를 다시 계산
  - 집계는 `analysis.py`의 함수만 부름
- **확인한 방법**: AI가 앱 내부 브라우저로 화면을 띄워 확인. 시설 체크를 하나 풀었을 때 숫자와 표가 바뀌는지 확인했고, 브라우저 콘솔 오류도 없었음. 시설을 하나도 고르지 않은 경우, 하루만 고른 경우, 해당 불량이 없는 경우도 함수로 직접 호출해 오류가 없는지 확인.
- **AI가 테스트 중 고친 부분**:
  - 급증 감지 호출 코드가 복잡하게 나뉘어 있어서, `detect_spikes`에 `defect_codes` 인자를 추가해 한 줄로 정리
  - 불량 위치 산점도의 y축이 −400부터 표시되는 문제를 발견해, 가로세로 비율 고정 옵션(`scaleanchor`)을 빼서 해결
- **직접 고친 부분**: README에 Dash 화면 캡처 4장을 "기능 여부" 항목으로 추가.

### S1~S6. 프로그램 구성

- **요청 내용**: PDF 4쪽 S1~S6 (함수를 별도 모듈로 분리, 설정 파일·명령 인자, 출력 폴더 자동 생성, 문제 파일 건너뛰기와 실행 로그, 인코딩 지정, 명령 한 줄 실행)
- **받은 결과**:
  - S1: 역할별 모듈 5개 (`config`, `loader`, `analysis`, `charts`, `writer`)
  - S2: 설정 값을 "기본값 ← config.json ← 명령 인자" 순서로 합치는 `load_config`
  - S3: 모든 저장이 거치는 `ensure_dir`
  - S4: `read_log_file`의 `try/except`와 필요한 열 검사, `run_log.txt`
  - S5: 읽기는 `utf-8-sig`, CSV 저장도 `utf-8-sig`(엑셀 한글 깨짐 방지), 텍스트는 `utf-8`
  - S6: `python main.py`
- **확인한 방법**: S4는 일부러 망가뜨린 파일 3개를 섞어 넣고 실행했습니다.
  - 열이 없는 `facility_D_log.csv`
  - 인코딩이 깨진 `facility_E_log.csv`
  - 빈 파일 `facility_F_log.csv`

  세 파일 모두 건너뛰었고, 이유가 `run_log.txt`에 남았으며, 나머지 결과는 정상으로 나왔습니다. S3는 output 폴더를 지운 뒤 다시 실행해 자동으로 만들어지는지 확인했습니다.
- **직접 고친 부분**: `writer.py`의 `save_csv`, `save_text`에 설명(docstring) 추가.

## 5. AI 결과를 그대로 쓰지 않고 확인한 것

- **숫자 검증**: 처리 결과의 숫자를 원본 CSV에서 따로 센 숫자와 비교했습니다 (전체 5,198건, 불량 238건, 시설별 101 / 56 / 81건).
- **예외 상황 테스트**: 망가진 파일, 시설 0개 선택, 결과 0건 같은 경우를 실제로 넣어 보고 오류 2건을 찾아 고쳤습니다 (F8, D 항목 참고).
- **설계 결정 확인**: AI가 정한 판단 기준 세 가지를 README에 적어 두고, 발표에서 설명할 수 있게 이해했습니다.
  - D99를 불량에 넣을지
  - 불량 종류를 골랐을 때 불량률을 어떻게 계산할지
  - 급증을 무엇으로 판단할지
- **코드 이해**: 요구사항별 구현 설명, UML, 함수별 설명을 차례로 요청해 받아 읽고, 이해한 내용을 바탕으로 `loader.py`, `writer.py`, `main.py`에 주석을 직접 보강했습니다.

## 6. AI 활용에서 배운 점

> 초안입니다. 본인이 실제로 느낀 점으로 고쳐 쓰세요.

- **요구사항 문서를 통째로 주면** 구조가 잘 잡힌 코드가 빠르게 나온다. 다만 요구사항이 애매한 부분(불량 종류 선택 시 불량률 계산 등)은 AI가 스스로 정하므로, 무엇을 정했는지 꼭 다시 물어봐야 한다.
- **"돌아간다"와 "맞다"는 다르다.** 처음 실행은 성공했지만, 결과가 0건인 경우를 테스트하자 오류가 나왔다. 정상 데이터 말고 극단적인 경우를 따로 시험해야 한다.
- **설명을 요청하는 것도 활용이다.** 요구사항별 → 파일별(UML) → 함수별로 점점 자세히 설명을 받으니 코드 전체를 이해하는 데 도움이 됐다.
